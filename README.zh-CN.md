# RepairScope-Bench

> **v2.0 严格试点：**仓库现包含 12 对、24 道单事实反事实任务，分别评价
> 恢复范围与真实执行浪费，使用终态枚举和公开工具重放验证 gold，并记录
> 可复用的机制卡、结构复杂度和实测难度校准。详见
> [docs/V2_PILOT.zh-CN.md](docs/V2_PILOT.zh-CN.md)。v1.1 保持冻结以便复现。

**当多步任务已经产生若干真实承诺、随后执行受阻时，Agent 能否自行调查，
完成剩余目标，并避免选择一个被其他可行恢复方案客观支配的回退范围？**

RepairScope-Bench v1.1 从统一、可执行的失败状态开始。此前的工具调用已经
产生付费且持续生效的机票、酒店、设备、许可证、订阅或服务合同。模型需要
查询订单、候选资源、取消预览、兼容关系和合同条款，并在 15 轮内通过领域
工具完成恢复。

公开主榜只有一种任务：**完整恢复**。

- `Goal Pass`：所有硬目标和业务规则都满足；
- `Non-Dominated Repair Pass`：先满足 Goal Pass，并且不存在另一个可行
  恢复在不可逆损失和恢复后净支出两项上都不差、且至少一项严格更好。

评测不使用 LLM judge、主观效用权重、直接汇总全局损失的工具、作者手写
恢复宏动作或专用 `finish()`。

## v1.1 数据

| 维度 | 覆盖 |
|---|---:|
| 领域 | 旅行、售后采购、SaaS、活动物流 |
| 独立基础情境 | 80 |
| 单事实反事实任务 | 160 |
| 核心推理结构 | 10 |
| 每个“推理结构 × 领域”单元 | 4 题 |
| 最大模型轮次 | 15 |

十类推理结构为：

1. 沉没成本与边际恢复成本；
2. 多跳经济影响传播；
3. 共享承诺保护；
4. 非线性阈值效应；
5. 条件合同逻辑；
6. 部分数量回退；
7. 桥接修复与上游替换；
8. 联合组合选择；
9. 明确期限内的长期成本；
10. 真正的 Pareto 权衡。

每种结构都在四个领域中出现，每个领域包含两个基础情境及其成对版本。
退款、违约金、返利、保修、许可证、订阅、押金、配送费和适配器只是经济
后果的载体，不被当作独立能力。

## 模型实际看到什么

生成器先从空数据库开始，用模型也可调用的公开写工具建立前序承诺，再
真实执行一次不可用选项并记录失败结果，最后保存并哈希失败快照。

模型只收到：

- 常规领域 Agent 系统提示；
- 用户的自然语言目标；
- 精简的成功前序工具轨迹；
- 最新一次失败调用及结果；
- 八个领域工具。

推理类别、反事实配对、被改变的事实、硬约束 DSL、可行终态和 Pareto
前沿均不向模型公开。模型必须主动查询才能发现退款、阈值、兼容和合同
条件。模型停止调用工具或达到 15 轮后，评测器直接读取持久状态；终止话术
不影响分数。

## 为什么 gold 是客观的

所有金额都来自订单、取消预览、合同和交易账本：

```text
irreversible_loss
  = 已有承诺未能退回的金额
  + 触发的违约/返利追回/迁移等费用
  + 恢复过程中多余购买后造成的损失

net_recovery_outlay
  = 失败边界之后新增支付和明确期限内的持续费用
  + 新触发费用
  - 实际退款
```

如果 A 在两项上都不差于 B，且至少一项更好，则 A 支配 B。所有非支配
方案都接受，因此无需人为规定“损失 1 元相当于多支出多少元”。

## 数据有效性门禁

`scripts/build_v11.py` 会拒绝以下任务：

- 无法从公开工具精确重放失败边界或快照哈希不一致；
- 少于三个可行语义恢复范围；
- 没有任何受支配的诱导方案；
- 终态枚举器与公开工具状态搜索得到不同前沿；
- 反事实对不只改变一个逻辑事实，或改变后 gold 范围不翻转；
- 参考恢复无法在 15 轮内执行。

最终数据中：

- 50% 题目具有多个 Pareto 非支配终态；
- 50% 题目的可接受方案包含非零不可逆损失；
- 90% 题目的 gold 至少改变一个既有承诺；
- 30% 题目无法靠新增一个选项完成。

## 安装、验证与基线

```bash
python -m pip install -e .
python scripts/build_v11.py
repairscope validate data/v11
repairscope run-baselines data/v11
python -m unittest discover -s tests -v
```

| 基线 | Goal Pass | Non-Dominated Pass |
|---|---:|---:|
| 不修复 | 0 / 160 | 0 / 160 |
| 只做局部修复 | 160 / 160 | 72 / 160 |
| 依赖闭包修复 | 160 / 160 | 72 / 160 |
| 全部撤销 | 160 / 160 | 0 / 160 |
| 只看新增标价 | 160 / 160 | 96 / 160 |
| 只追求最大退款 | 160 / 160 | 0 / 160 |
| 最少改动 | 160 / 160 | 72 / 160 |
| Pareto Oracle | 160 / 160 | 160 / 160 |

“精确最小化不可逆损失”或“精确最小化净支出”本身是 Oracle 上界，不是
现实的弱启发式；在正确处理并列项后，任一维度的全局最小值必然非支配。

## 运行模型

```bash
repairscope run-suite data/v11 \
  --provider openai-compatible \
  --model YOUR_MODEL_ID \
  --base-url https://gateway.example/v1 \
  --repeats 5 \
  --output-dir results/your-model-v11
```

正式实验每题独立运行五次，同时报告 Goal Pass@1/Pass^5、
Non-Dominated Repair Pass@1/Pass^5、受支配恢复率、两项 regret、反事实
成对成功率，以及领域、推理结构和难度分项。

## 研究边界

v1.1 使用四套领域化工具表面和状态字段，共享一个可审计的承诺—交易账本
内核，从而保证跨领域精确比较。v0.6 保留了此前直接接入 STATE-Bench
旅行与售后运行时的实现。

本工作的创新不是“首次提出部分回退”，而是客观评测：Agent 在已有真实
承诺的失败状态中，是否会完成任务却选出一个被其他可行方案严格经济支配的
恢复范围。当前版本不评测失败前规划、主观偏好询问或生产环境安全性。
