# RepairScope-Bench

RepairScope-Bench 评测一个受控问题：当多步任务已经产生若干持久外部承诺，随后某个操作失败时，Agent 能否自行查询环境、完成剩余目标，并避免修复过程造成不必要的额外损失。

当前版本是 **v0.4.0 研究原型**，包含 4 个反事实家族、16 个任务。所有模型从同一个权威失败状态开始；每题最多 15 轮，正式协议每题独立运行 5 次。

## v0.4.0 的关键设计

模型只看到：

- 自然语言客户请求；
- 失败前公开工具活动；
- 最新一次失败结果；
- 旅行或购物领域工具。

模型不会看到：

- “先最小化额外损失、再最小化总成本”的评测器指令；
- 全局 `recovery_loss` 或成本汇总；
- 隐藏约束、完整目录、gold 范围或 oracle 轨迹。

旅行任务使用预订、酒店、租车、搜索、取消预览和改签工具；购物任务使用订单、商品搜索、退货预览、换货和兼容性工具。取消或退货预览只返回原价、退款额和费用，模型必须自行组合订单、政策、库存、兼容性与价格事实。

本 benchmark 测的是自主恢复范围选择，而不是“是否倾向再次询问用户”。协议明确题目和工具已经提供决策所需的信息：Agent 不得把候选方案交还用户选择，必须自行决定并执行，完成后调用 `finish`；只有客观不可解时才调用 `report_infeasible`。该规则不披露损失公式、优化顺序或 gold。

旅行接口保留了 STATE-Bench 将航班预订、酒店预订和租车记录分开，并分别提供列表、详情和搜索工具的领域结构；本仓库为“已产生承诺后的损失”新增定向退款/改签报价与独立交易账本。没有直接复制或暗改 STATE-Bench runtime。

## 数据门槛

12 个可解任务全部满足：

1. 至少存在两条能够完成硬目标的修复路径；
2. 不同路径会处理不同的既有承诺，或采用修改与取消重订等不同操作；
3. 至少两条可行路径的客观 `recovery_loss` 不同；
4. 决定差异的退款、修改费、退货费、库存或兼容性只能通过工具发现。

另外包含 4 个不可解控制题。构建器和验证器会自动拒绝退化成“只有唯一可行路径”或“可行路径损失完全相同”的 `loss_sensitive` 任务。

## 四个任务家族

| 家族 | 固定失败状态 | 可行修复范围示例 |
|---|---|---|
| 目的地酒店 | 航班已改到 SFO，目标酒店售罄 | 保留旧酒店、取消重订、原地改订、不可解 |
| 缩短行程 | 行程缩短，租车日期修改失败 | 付费修改、取消重订、保留额外一天、不可解 |
| 办公设备 | 笔记本和显示器已购买，扩展坞因不兼容作废 | 买转接型扩展坞、换货笔记本、退货重买、不可解 |
| 丹佛套餐 | 航班和酒店已确认，租车失败且有预算 | 保留既有安排、换酒店、换航班、不可解 |

## 客观账本

评测器从交易记录计算：

```text
recovery_loss =
    已有承诺取消后的未退款金额
  + 恢复期间新购后又取消的未退款金额
  + 原地修改产生的正向净现金支出
```

硬目标满足后，隐藏评测器使用：

```text
(recovery_loss,
 lifecycle_cost,
 mutated_prior_commitments,
 state_changing_actions)
```

模型只收到自然的“不要浪费钱或撤销仍然有用的安排”要求，不会收到上述元组。

## 安装与验证

```powershell
python -m pip install -e .
python scripts/build_pilot.py
repairscope validate data/pilot
python -m unittest discover -s tests -v
repairscope run-baselines data/pilot
```

当前简单策略结果：

| 策略 | 完成 | 最优 |
|---|---:|---:|
| 不修复 | 2 / 16 | 2 / 16 |
| 只处理缺失步骤 | 2 / 16 | 2 / 16 |
| 处理声明受影响步骤 | 0 / 16 | 0 / 16 |
| 全部回退 | 0 / 16 | 0 / 16 |
| 穷举 oracle | 16 / 16 | 16 / 16 |

正式运行默认每题 5 次，同时报告 Goal/Optimal Pass@1 与严格 Pass^5。单次结果只能作为 smoke test。
