# RepairScope-Bench

**当工具 Agent 已经产生持久承诺、随后执行失败时，它能否完成剩余目标，同时避免选择一个被其他可行方案客观经济支配的恢复范围？**

RepairScope-Bench v1.0 从统一、可重放的失败快照开始评测。模型需要自行查询已有承诺、候选资源、退款预览、兼容关系和合同条款，再通过领域工具修改持久状态。

评测区分两个结果：

- `Goal Pass`：全部硬目标和业务规则均满足；
- `Non-Dominated Repair Pass`：完成目标，且不存在另一个可行恢复在不可逆损失和恢复期净支出上都不差、至少一项严格更好。

评测不使用 LLM judge、人工效用权重、直接汇总全局损失的工具或 `finish()` 协议。

## v1.0 数据

默认数据包含 80 个基础失败情境，每个情境生成一对只改变一个可查询事实的反事实任务，共 160 题。

| 维度 | 数量 |
|---|---:|
| 领域 | 4 |
| 基础失败情境 | 80 |
| 反事实任务 | 160 |
| 核心推理结构 | 10 |
| 每题模型轮次上限 | 15 |

四个领域为旅行、售后采购、SaaS 和活动物流。十种推理结构为：

1. 沉没成本与边际恢复成本；
2. 多跳经济影响传播；
3. 共享承诺保护；
4. 非线性阈值效应；
5. 条件合同逻辑；
6. 部分数量回退；
7. 桥接修复与上游替换；
8. 联合兼容组合选择；
9. 明确期限下的长期成本；
10. 真正的 Pareto 权衡。

每种结构在每个领域各有两个基础情境。退款、违约金、许可证、保修、订阅、押金和数量折扣只是经济载体，不再直接作为能力类别。

旅行和售后 adapter 延续 STATE-Bench 的领域工作流与工具语义；保留的 v0.6 数据提供此前直接接入 STATE-Bench runtime 的版本。SaaS 和活动物流使用 v1 的持久承诺运行时。

## 数据构造

`scripts/build_v1.py` 对每题执行：

1. 从空状态开始；
2. 使用与模型相同的公开写工具创建四个付费承诺；
3. 实际调用一个不可用选项并记录失败；
4. 保存并哈希失败快照；
5. 构造只改变一个事实的配对版本；
6. 从原始资源、合同和硬目标自动枚举全部可行终态；
7. 使用第二套公共工具搜索器重放并校验 Pareto frontier。

任务文件不包含 `oracle_actions` 或 `candidate_scopes`。必要恢复操作的先后顺序不会改变经济结果；模型额外购买、取消或重复修改产生的浪费仍会进入实际账本。

## 安装与验证

```bash
python -m pip install -e .
python scripts/build_v1.py
repairscope validate data/v1
repairscope run-baselines data/v1
python -m unittest discover -s tests -v
```

当前确定性 baseline：

| 策略 | Goal Pass | Non-Dominated Pass |
|---|---:|---:|
| 不修复 | 0 / 160 | 0 / 160 |
| 只做局部修复 | 160 / 160 | 80 / 160 |
| 依赖范围修复 | 160 / 160 | 80 / 160 |
| 全量回退 | 160 / 160 | 0 / 160 |
| 只看最终标价 | 160 / 160 | 96 / 160 |
| 只看退款额 | 160 / 160 | 0 / 160 |
| Pareto Oracle | 160 / 160 | 160 / 160 |

60% 的任务具有多个 Pareto 非支配终态；60% 的任务至少有一个不可逆损失大于零的正确方案。

需要注意：如果一个算法能够穷举全部可行方案并精确最小化某个 Pareto 维度，它在正确处理并列结果时必然能找到非支配点。因此“只最小化损失的精确 Oracle”属于理论上界，不是现实启发式，也不能用来声称 benchmark 被简单规则攻破。

## 模型实验

```bash
repairscope run-suite data/v1 --provider openai \
  --model YOUR_MODEL_ID --repeats 5 --output-dir results/openai-v1
```

同一接口支持 Anthropic、Qwen、DeepSeek 和 OpenAI-compatible 网关。结果同时汇报 Goal Pass、Non-Dominated Repair Pass、受支配恢复率、两类 regret、反事实对成功率，以及按领域、推理结构和难度的分组表现。

本工作的创新不是首次提出“部分回退”，而是系统评测 Agent 是否能够对已经执行的承诺进行恢复范围推理，并避免一个被其他可行恢复严格经济支配的结果。
